# 项目核心思路

> 记录时间: 2025-12-25

---

## 一、项目定位

**DUSt3R 轻量化（部署导向）**

- **目标论文级别**：IEEE Access 水平
- **性质**：可写论文 + 可落地跑通的工程项目

---

## 二、核心目标

把 DUSt3R 这类 feed-forward 3D 重建/匹配体系做**轻量化**：
- 速度 ↑
- 显存 ↓
- 模型体积 ↓
- 能耗 ↓

**同时尽量保持可用精度**

并形成一套**可复现实验矩阵**，支撑论文与工程交付。

---

## 三、技术手段候选

| 方法 | 说明 |
|------|------|
| **蒸馏 (Distillation)** | Teacher → Student |
| **剪枝 (Pruning)** | 结构化/非结构化裁剪 |
| **量化 (Quantization)** | PTQ / QAT |
| **低秩分解** | 权重共享、模块替换 |
| **架构替换** | 替换重模块为更轻 backbone 或更小的 attention 变体 |
| **平台适配** | 不同硬件下的端到端测试与对比 |

---

## 四、交付形态

不仅"跑分"，还要能给出：

1. **统一 Benchmark**
2. **推理链路**
3. **资源指标**：
   - Latency / FPS
   - VRAM
   - Model size
   - Energy / 功耗估计
4. **可复现脚本与配置**

---

## 五、主要风险点（需警惕）

### 风险 1：论文贡献不够硬

> "只做轻量化"可能沦为工程调参报告

**对策**：需要把贡献做成：
- 系统性方法
- 可泛化结论
- 强基线对比

### 风险 2：评估闭环虚

> 没有明确数据集、任务定义、指标、统一训练/推理协议，结果会被认为不可比

**对策**：
- 明确数据集
- 明确任务定义
- 明确指标
- 统一训练/推理协议

### 风险 3：平台测试不是贡献

> 平台测试只能当支撑材料，不能当核心创新

**对策**：核心还是要有：
- 方法论
- 机制解释
