## 📌 核心前提：Teacher架构确认

基于已验证的DUSt3R架构（[DUSt3R完整架构文档.md](DUSt3R完整架构文档.md)）：

| 组件 | Teacher配置 | 来源 |
|------|-------------|------|
| **Encoder** | ViT-Large: 24层, 1024维, 16头 | ✅ 论文 + 代码 |
| **Decoder** | ViT-Base × 2（独立权重）: 12层, 768维, 12头 | ✅ 代码验证 (deepcopy) |
| **输出头** | DPT多尺度融合 | ✅ 论文Section 4 |
| **总参数** | ~571M | ✅ HuggingFace |
| **位置编码** | RoPE（继承自CroCo） | ✅ 论文 |

**关键设计点**:
1. **Encoder权重共享**：两张图像使用同一个Encoder (Siamese manner)
2. **Decoder权重独立**：`dec_blocks2 = deepcopy(dec_blocks)`，两个Decoder各自独立
3. **Cross-Attention**：Decoder中每个token同时attend to两个视图的信息

### 方案B：异构设计（Heterogeneous Design）

针对DUSt3R特点优化：

#### Student-H（Heterogeneous）

**核心思路**：Encoder是特征提取的关键，Decoder负责融合和输出

| 组件 | 策略 | 参数 |
|------|------|------|
| **Encoder** | 轻量化但保持表达力 | 18层, 768维, 12头 |
| **Decoder** | **共享权重** | 8层×1 + 共享 |
| **DPT头** | 简化 | 减少hooks层 |
| **预估参数** | - | **~280M** |

**关键变化**：
- 将Teacher的两个独立Decoder改为**单个共享Decoder**
- 用额外的视图标识token区分两个视图
- 减少冗余参数，但可能需要更多蒸馏轮次

## 📐 蒸馏损失设计

### 损失函数公式

$$
\mathcal{L}_{total} = \alpha \cdot \mathcal{L}_{task} + \beta \cdot \mathcal{L}_{KD} + \gamma \cdot \mathcal{L}_{FD}
$$

### 各损失组件

#### 1. Task Loss（任务损失）

沿用DUSt3R原损失（ConfLoss + Regr3D）：

$$
\mathcal{L}_{task} = \sum_i C_i \cdot \ell_{regr}(v,i) - \alpha_{conf} \cdot \log(C_i)
$$

其中 $\ell_{regr}$ 为归一化后的L2距离：

$$
\ell_{regr}(v,i) = \left\| \frac{1}{z} X_i^{v,1} - \frac{1}{\bar{z}} \bar{X}_i^{v,1} \right\|_2
$$

#### 2. KL Divergence Loss（知识蒸馏损失）

在pointmap输出上计算softmax后的KL散度：

$$
\mathcal{L}_{KD} = T^2 \cdot \text{KL}\left( \text{softmax}\left(\frac{p_T}{T}\right) \| \text{softmax}\left(\frac{p_S}{T}\right) \right)
$$

- $T$: 温度参数（候选值：3, 5）
- $p_T, p_S$: Teacher和Student的展平输出

**注意**：由于DUSt3R输出是连续的3D坐标而非分类logits，需要特殊处理：
- 方案1：在展平后应用softmax（当前实现）
- 方案2：直接使用MSE Loss作为软蒸馏

#### 3. Feature Distillation Loss（特征蒸馏损失）

从Encoder的多层提取特征进行匹配：

$$
\mathcal{L}_{FD} = \sum_{l \in \text{hooks}} \| f_T^l - \text{proj}(f_S^l) \|_2^2
$$

- $f_T^l, f_S^l$: Teacher/Student第$l$层特征
- proj: 维度匹配投影层（如Student维度较小）

### 课程式蒸馏策略

```
训练进度:  0% ─────────────── 70% ─────────────── 100%
                              │
Task权重:  α = 1.0            │           α = 0.6
KD权重:    β = 0.5            │           β = 0.8
FD权重:    γ = 0.0            │           γ = 0.1
```

**原理**：前期让Student学习基础任务，后期强化对Teacher的模仿

## 🔄 训练流程

### Phase 1: Encoder预热（可选）

如果Student Encoder是从头训练：
1. 冻结Decoder，只训练Encoder
2. 使用Teacher Encoder的输出作为监督
3. 约5-10 epochs

### Phase 2: 端到端蒸馏

```python
for epoch in range(max_epochs):
    # 课程式调整权重
    progress = epoch / max_epochs
    if progress > curriculum_pct:  # 70%后
        beta = beta_final  # 0.5 → 0.7
        gamma = gamma_final  # 0.0 → 0.1
    
    for batch in train_loader:
        # Teacher前向（不计算梯度）
        with torch.no_grad():
            teacher_out = teacher(batch['img1'], batch['img2'])
        
        # Student前向
        student_out = student(batch['img1'], batch['img2'], return_features=True)
        
        # 计算损失
        loss = compute_distill_loss(student_out, teacher_out, batch)
        
        # 反向传播
        optimizer.zero_grad()
        loss.backward()
        torch.nn.utils.clip_grad_norm_(student.parameters(), grad_clip)
        optimizer.step()
```

### Phase 3: 精调（Optional）

蒸馏完成后，用小学习率在真实GT上微调：
- 学习率：1e-5
- 轮次：5-10
- 目的：消除Teacher偏差

## 🔌 与后续步骤对接

### K → Q（蒸馏后量化）

蒸馏产出的Student模型作为量化的输入：

```
Student-S (FP32, ~200M)
    ↓ PTQ/QAT
Student-S-INT8 (~50M, 4x压缩)
```

**关键**：蒸馏要让Student分布稳定，便于量化校准

### K → P（蒸馏后剪枝）

或者先剪枝Teacher，再蒸馏：

```
Teacher (571M)
    ↓ 结构化剪枝 (ρ=0.1)
Teacher-Pruned (514M)
    ↓ 蒸馏
Student-from-Pruned
```
