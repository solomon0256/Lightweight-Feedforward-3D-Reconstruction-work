# Smoke Gate 和 Trend Gate 功能验证报告

## 📋 需求文档要求 vs 现有实现对比

### 需求文档要求

根据 `docs/验证脚本需求.md`，需要两个脚本：

#### 脚本1：轻量化结果正确性验证脚本
**目的**：用1个样本验证轻量化后的**结果**是否正确

**验证内容**：
- [ ] 蒸馏：跑1个样本，检查loss是否正常下降
- [ ] 量化：跑1个样本，检查输出格式和数值是否正确
- [ ] 剪枝：跑1个样本，检查稀疏度是否达到目标

**验证逻辑**：
```
1. 跑1个样本的蒸馏 → 检查loss是否下降 → 下降说明蒸馏正确
2. 跑1个样本的量化 → 检查输出是否正确 → 正确说明量化正确
3. 跑1个样本的剪枝 → 检查稀疏度是否达标 → 达标说明剪枝正确
4. 如果1个OK → 服务器跑1000个也OK
```

**运行时机**：**在运行轻量化脚本之前**，验证轻量化过程本身

---

#### 脚本2：性能达标验证脚本
**目的**：用1个样本验证轻量化后的**性能**是否符合预期

**验证内容**：
- [ ] 参数量：Student模型参数量是否达到压缩目标
- [ ] 推理速度：1个样本的推理时间是否达到加速目标
- [ ] 精度：1个样本的输出精度是否在可接受范围
- [ ] 输出格式：输出shape和数据类型是否正确

**运行时机**：**在运行轻量化脚本之前**，预估性能

---

### 现有实现分析

#### smoke_gate.py 实际功能

**当前实现**：
- ✅ Schema 断言检查（输出字段、shape、dtype）
- ✅ Golden 对比（与 baseline 标准答案对比）
- ✅ 稳定性检查（NaN/Inf 检测）
- ⚠️ 轻量化过程验证（`verify_lightweighting_process`）：只检查 checkpoint 能否加载，**不验证轻量化过程本身**

**运行时机**：**在轻量化脚本运行之后**，验证已完成的模型

**缺失功能**：
- ❌ **不验证蒸馏 loss 是否下降**（需要实际运行训练步骤）
- ❌ **不验证量化过程是否正确**（只检查量化后的模型能否加载）
- ❌ **不验证剪枝稀疏度是否达标**（只检查 checkpoint 是否存在）

---

#### trend_gate.py 实际功能

**当前实现**：
- ✅ 精度护栏检查（与 baseline 对比，检查精度下降是否超限）
- ✅ 性能护栏检查（延迟、显存对比）
- ✅ 趋势分析（200对样本的统计）

**运行时机**：**在轻量化脚本运行之后**，验证已完成的模型性能

**缺失功能**：
- ❌ **不预估参数量**（需要加载模型后才能测量）
- ❌ **不预估推理速度**（需要实际推理）
- ❌ **不预估精度**（需要实际评测）

---

## 🔍 核心问题

### 问题1：运行时机不匹配

| | 需求文档 | 现有实现 |
|--|---------|---------|
| **运行时机** | 轻量化脚本**之前** | 轻量化脚本**之后** |
| **验证对象** | 轻量化**过程** | 轻量化**结果** |

### 问题2：验证内容不匹配

| 验证项 | 需求文档要求 | smoke_gate.py | trend_gate.py |
|--------|-------------|---------------|---------------|
| **蒸馏 loss 下降** | ✅ 需要 | ❌ 没有 | ❌ 没有 |
| **量化输出正确** | ✅ 需要 | ⚠️ 只检查格式 | ❌ 没有 |
| **剪枝稀疏度** | ✅ 需要 | ⚠️ 只检查存在 | ❌ 没有 |
| **参数量预估** | ✅ 需要 | ❌ 没有 | ❌ 没有 |
| **速度预估** | ✅ 需要 | ❌ 没有 | ⚠️ 需要已完成的模型 |
| **精度预估** | ✅ 需要 | ❌ 没有 | ⚠️ 需要已完成的模型 |

## ✅ 现有实现能做什么

### smoke_gate.py 能做的：
1. ✅ 验证已完成的轻量化模型的输出格式是否正确
2. ✅ 验证已完成的轻量化模型的输出数值是否与 baseline 一致（Golden 对比）
3. ✅ 验证已完成的轻量化模型是否稳定（无 NaN/Inf）

### trend_gate.py 能做的：
1. ✅ 验证已完成的轻量化模型的精度是否达标（与 baseline 对比）
2. ✅ 验证已完成的轻量化模型的性能是否达标（延迟、显存）
3. ✅ 在小规模数据集（200对）上预测最终性能趋势

---

## ❌ 现有实现不能做什么

### smoke_gate.py 不能做的：
1. ❌ **在运行轻量化脚本之前**验证蒸馏 loss 会下降
2. ❌ **在运行轻量化脚本之前**验证量化过程会成功
3. ❌ **在运行轻量化脚本之前**验证剪枝稀疏度会达标

### trend_gate.py 不能做的：
1. ❌ **在运行轻量化脚本之前**预估参数量
2. ❌ **在运行轻量化脚本之前**预估推理速度
3. ❌ **在运行轻量化脚本之前**预估精度

---

## 🎯 结论

### 现有实现 vs 需求文档

| 方面 | 匹配度 | 说明 |
|------|--------|------|
| **运行时机** | ❌ 不匹配 | 需求：轻量化之前；现有：轻量化之后 |
| **验证对象** | ❌ 不匹配 | 需求：验证过程；现有：验证结果 |
| **功能覆盖** | ⚠️ 部分匹配 | 现有功能有用，但不满足需求文档的要求 |

### 建议

1. **保留现有实现**：`smoke_gate.py` 和 `trend_gate.py` 对验证已完成的模型很有用

2. **补充新脚本**：按照需求文档创建：
   - `scripts/verify_lightweight_feasibility.py` - 验证轻量化过程（蒸馏/量化/剪枝）
   - `scripts/verify_performance.py` - 预估性能（参数量/速度/精度）

3. **使用流程**：
   ```
   轻量化之前：
   → verify_lightweight_feasibility.py（验证过程）
   → verify_performance.py（预估性能）
   
   轻量化之后：
   → smoke_gate.py（验证格式）
   → trend_gate.py（验证性能趋势）
   ```
