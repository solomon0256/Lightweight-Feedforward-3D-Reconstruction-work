# 两个门禁的本质与实现思路

> **思考日期**: 2025-12-27  
> **目的**: 从工程本质重新思考两个门禁的实现

## 🎯 核心目标（重新理解）

### 问题背景

- **环境限制**：工作电脑性能不高，不能长时间运行
- **成本控制**：避免在服务器上运行失败的实验
- **验证需求**：确保轻量化后的模型能正确运行且性能可接受

### 两个门禁的本质

#### 门禁1：Smoke Gate（冒烟测试）

**本质**：快速验证轻量化后的模型能否正常运行

**类比**：汽车出厂前的"点火测试"
- 不要求跑完全程
- 只要求能启动、能跑一小段、不出故障
- 如果连启动都失败，就不用上高速了

**要验证什么**：
1. 模型能否加载（轻量化过程是否成功）
2. 模型能否运行推理（不会崩溃）
3. 输出格式是否正确（Schema）
4. 输出数值是否合理（无NaN/Inf，与baseline一致）

**实现思路**：
- 用16对样本快速跑一遍
- 检查输出格式、数值合理性、稳定性
- 如果通过，说明"能跑"，可以进入下一步

---

#### 门禁2：Trend Gate（趋势预警）

**本质**：在小规模数据上预测大规模运行的结果

**类比**：天气预报
- 不需要观测所有天气数据
- 用局部数据预测整体趋势
- 如果趋势不好，提前预警

**要验证什么**：
1. 精度下降是否在可接受范围
2. 性能变化是否合理
3. 不同阶段/不同压缩率有不同的阈值要求

**实现思路**：
- 用200对样本跑一遍
- 计算精度和性能指标
- 与baseline对比，检查是否在阈值内
- 阈值需要根据训练阶段/压缩率动态调整

## 🔧 实现思路（从零开始）

### Smoke Gate 实现思路

#### 核心流程

```
1. 加载轻量化后的模型
   ├─ 蒸馏（K）：加载 student 模型
   ├─ 量化（Q）：加载量化后的模型
   └─ 剪枝（P）：加载剪枝后的模型

2. 运行推理（16对样本）
   ├─ 加载图像对
   ├─ 运行模型推理
   └─ 收集输出

3. 验证输出
   ├─ Schema 检查：字段、dtype、shape
   ├─ Golden 对比：与 baseline 输出对比
   └─ 稳定性检查：NaN/Inf/崩溃率

4. 输出结果
   └─ 通过/失败 + 详细报告
```

#### 关键实现点

**1. 模型加载**
- 需要统一的模型加载接口
- 支持三种轻量化方法（K/Q/P）
- 如果加载失败，立即报错

**2. 轻量化过程验证**
- 蒸馏：检查 student 模型是否存在、能否加载
- 量化：检查量化过程是否成功、量化后模型能否运行
- 剪枝：检查剪枝过程是否成功、剪枝后模型能否运行

**3. 输出验证**
- Schema：检查输出字段、dtype、shape
- Golden：与 baseline 输出对比（不同方法不同容差）
- 稳定性：检查 NaN/Inf/崩溃

---

### Trend Gate 实现思路

#### 核心流程

```
1. 加载轻量化后的模型（同 Smoke Gate）

2. 运行推理（200对样本）
   ├─ 加载图像对
   ├─ 运行模型推理
   └─ 收集输出和性能数据

3. 计算指标
   ├─ 精度指标：absrel, delta1, visloc_acc
   └─ 性能指标：延迟、显存

4. 获取阈值
   ├─ 根据方法类型（K/Q/P）
   ├─ 根据训练进度（蒸馏）或压缩率（剪枝）
   └─ 从配置文件读取对应阈值

5. 检查阈值
   ├─ 精度护栏：精度下降是否在阈值内
   └─ 性能护栏：性能变化是否合理

6. 输出结果
   └─ 通过/失败 + 详细报告
```

#### 关键实现点

**1. 分段阈值配置**

需要支持：
- **蒸馏**：按训练进度分段（0-10%, 10-50%, 50-100%）
- **量化**：按量化精度（FP16/INT8）
- **剪枝**：按剪枝率分段（20%, 40%, 60%）

2. **阈值查找函数**

```python
def get_threshold_for_stage(method, variant, progress=None, flops_reduction=None):
    """
    根据方法、阶段、压缩率获取阈值
    
    实现：
    1. 从配置文件读取阈值配置
    2. 根据 progress 或 flops_reduction 查找对应阶段
    3. 如果配置了多个阶段，支持线性插值
    4. 返回阈值字典
    """
    config = load_config('config/eval_contract.yaml')
    
    if method == 'K':  # 蒸馏
        stages = config['guardrails']['accuracy']['distillation']['stages']
        # 根据 progress 查找对应阶段
        for stage in stages:
            if stage['progress_range'][0] <= progress <= stage['progress_range'][1]:
                return stage
        # 如果不在任何阶段，使用线性插值
        return interpolate_threshold(stages, progress)
    
    elif method == 'P':  # 剪枝
        stages = config['guardrails']['accuracy']['pruning']['stages']
        # 根据 flops_reduction 查找对应阶段
        for stage in stages:
            if abs(stage['flops_reduction_pct'] - flops_reduction) < 5:
                return stage
        # 如果不在任何阶段，使用线性插值
        return interpolate_threshold(stages, flops_reduction)
    
    elif method == 'Q':  # 量化
        return config['guardrails']['accuracy']['quantization'][variant]
```

## 💡 关键洞察

### 1. Smoke Gate 的本质

**不是验证脚本，而是验证模型**

- 脚本验证：检查代码逻辑是否正确
- 模型验证：检查轻量化后的模型能否正常运行

**关键区别**：
- 脚本验证：用 mock 数据测试代码
- 模型验证：用真实数据运行真实模型

### 2. Trend Gate 的本质

**不是固定阈值，而是动态阈值**

- 固定阈值：所有阶段用同一个阈值
- 动态阈值：不同阶段/不同压缩率用不同阈值

**关键区别**：
- 固定阈值：简单但不灵活
- 动态阈值：复杂但更准确

### 3. 两个门禁的关系

**Smoke Gate → Trend Gate → 服务器**

- Smoke Gate：快速验证"能跑"
- Trend Gate：验证"跑得好"
- 服务器：最终验证"跑得完美"

**如果 Smoke Gate 失败，直接停止，不上服务器**
**如果 Trend Gate 失败，调整参数，重新验证**
