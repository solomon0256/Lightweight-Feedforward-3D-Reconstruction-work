# Pipeline 验证策略说明

## 核心思路

**用一个小型 Mock 模型代替真实的 DUSt3R，验证 PQK 代码逻辑是否正确。**

```
┌─────────────────────────────────────────────────────────────┐
│  Mock 模型 (159K 参数)    vs    DUSt3R (571M 参数)          │
├─────────────────────────────────────────────────────────────┤
│  - 几个卷积层 + 一个全连接层      - 完整的 ViT 架构          │
│  - 占用 < 10MB 显存              - 占用 ~3GB 显存           │
│  - 本地 RTX 3060 可运行           - 需要服务器 GPU           │
│  - 只验证代码逻辑                 - 验证真实效果              │
└─────────────────────────────────────────────────────────────┘
```

## 为什么这样做？

### 问题背景
1. DUSt3R 模型有 **5.71 亿参数**，需要 ~3GB 显存
2. 本地 RTX 3060 (6GB) 勉强能跑推理，但开发调试不方便
3. 服务器 GPU 按小时计费，调试代码太浪费钱
4. 如果代码有 bug，在服务器上发现就太晚了

### 解决方案
创建一个 **Mock 模型**：
- 结构简单（几个卷积层）
- 参数极少（159K vs 571M，小 3600 倍）
- 但**具备相同的接口**（输入输出形状一致）

## 验证逻辑

```
如果 Mock 模型能被成功：
  ✓ 剪枝 (Pruning)     → 剪枝代码正确
  ✓ 量化 (Quantization) → 量化代码正确  
  ✓ 蒸馏 (Distillation) → 蒸馏代码正确
  ✓ 保存/加载          → 检查点代码正确

那么：
  → 换成 DUSt3R 模型，代码也能正确执行
  → 只是处理的参数更多、时间更长
```

## Mock 模型结构

```python
class MockModel(torch.nn.Module):
    def __init__(self):
        super().__init__()
        # 编码器：2个卷积层
        self.encoder = torch.nn.Sequential(
            torch.nn.Conv2d(3, 64, 3, padding=1),
            torch.nn.ReLU(),
            torch.nn.Conv2d(64, 128, 3, padding=1),
            torch.nn.ReLU(),
        )
        # 解码器：2个卷积层
        self.decoder = torch.nn.Sequential(
            torch.nn.Conv2d(128, 64, 3, padding=1),
            torch.nn.ReLU(),
            torch.nn.Conv2d(64, 3, 3, padding=1),
        )
        # 全连接层（用于测试剪枝）
        self.fc = torch.nn.Linear(128, 64)
    
    def forward(self, x):
        # 输入: [batch, H, W, 3]
        # 输出: [batch, H, W, 3]
        x = x.permute(0, 3, 1, 2)  # → [batch, 3, H, W]
        x = self.encoder(x)
        x = self.decoder(x)
        x = x.permute(0, 2, 3, 1)  # → [batch, H, W, 3]
        return x
```

**关键点**：
- 输入输出形状与 DUSt3R 一致：`[batch, 384, 512, 3]`
- 包含 Conv2d 层（可测试量化）
- 包含 Linear 层（可测试剪枝）
- 有 encoder-decoder 结构（可测试蒸馏）

## 验证内容对照表

| 测试项 | Mock 模型验证 | 真实模型验证 |
|--------|--------------|-------------|
| 模型加载 | ✓ 代码能正确创建模型 | ✓ 能加载预训练权重 |
| 推理 | ✓ forward() 能执行 | ✓ 输出有意义的结果 |
| 剪枝 | ✓ 能对 Linear 层剪枝 | ✓ 剪枝后精度变化 |
| 量化 | ✓ INT8/FP16 转换成功 | ✓ 量化后精度变化 |
| 蒸馏 | ✓ 损失计算+梯度回传 | ✓ Student 学到知识 |
| 保存/加载 | ✓ checkpoint 格式正确 | ✓ 能恢复训练状态 |

## 使用方式

### 本地轻量验证（开发时）
```bash
python scripts/verify_pipeline.py --all --light --device cuda
```
- 用 Mock 模型
- 几秒钟完成
- 验证代码逻辑

### 服务器完整验证（部署后）
```bash
python scripts/verify_pipeline.py --all --device cuda
```
- 用真实 DUSt3R 模型
- 需要几分钟
- 验证真实效果

## 类比解释

这就像**汽车测试**：

| 阶段 | 汽车测试 | 我们的验证 |
|------|---------|-----------|
| 设计验证 | 用模型车测试空气动力学 | 用 Mock 模型测试代码逻辑 |
| 实际测试 | 用真车跑测试赛道 | 用 DUSt3R 跑完整实验 |

模型车不能真的载人，但能验证设计是否正确。
Mock 模型不能做真正的 3D 重建，但能验证 PQK 代码是否正确。
