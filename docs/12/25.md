## 用户要求说明测定思路

**用户问**：现在说说所有这些参数的测定思路！

### 我的回答：Baseline 120+ 参数测定思路

#### 一、模型本体（6 个）- 静态分析，无需运行
- params_total: `sum(p.numel() for p in model.parameters())`
- params_encoder/decoder: 单独统计各模块参数
- flops: 用 `fvcore` 或 `thop` 库，固定输入 `[1,3,512,384]`
- macs: FLOPs / 2
- size_MB: `os.path.getsize(model.pth) / 1e6`

#### 二、显存（3 个）- 实际推理测量
- vram_peak: `torch.cuda.max_memory_allocated()` 在 forward 后
- vram_fp16: 同上，但 `model.half()` + `autocast`
- activation_memory: vram_peak - model_size（估算）
- 测量条件：BS=1，forward-only，先 `torch.cuda.reset_peak_memory_stats()`

#### 三、推理性能（7 个）- 多次运行统计
- t_pair_p50/p95/mean/std: 收集 N 次推理时间，计算统计量
- t_scene: 整个场景所有 pair 的总时间
- pairs_per_sec: num_pairs / t_scene
- 测量要求：warmup ≥ 10 次，测量 ≥ 100 次，`torch.cuda.synchronize()`

#### 四、精度/质量（45+ 个）- 需要 GT 数据集

**4.1 DUSt3R 官方（4 个）**
- L21: pred vs GT 的 L2 距离再取 L1
- Regr3D: 尺度归一化后的 3D 回归误差
- confidence: 模型输出 `conf` 字段平均值
- reproj_px: 3D 点投影回 2D 与 GT 的像素距离

**4.2 位姿估计（8 个）**
- pose_error/angular_error: 预测 vs GT 位姿误差
- acc@Xm,Y°: 误差 < X米 且 < Y度 的样本比例
- 需要有 GT 相机位姿的数据集

**4.3 深度/几何（8 个）**
- absrel: `mean(|pred - gt| / gt)`
- rmse: `sqrt(mean((pred - gt)²))`
- delta1/2/3: `mean(max(pred/gt, gt/pred) < 阈值)`
- 需要 GT 深度图

**4.4 点云/3D（6 个）**
- chamfer: 双向最近点距离平均
- f_score: 误差 < 阈值的点比例
- 需要 GT 点云或 mesh

**4.5 场景级别（4 个）**
- completeness/accuracy/coverage/num_matches

**4.6 匹配质量（4 个）**
- precision/recall/inlier_ratio/epipolar_error

#### 五、能耗（7 个）- 需要硬件监控
- gpu_power: `nvidia-smi --query-gpu=power.draw` 或 `pynvml`
- energy_per_pair: power_avg × t_pair
- thermal_throttling: 监控温度是否触发降频

#### 六、边缘设备（5 个）- 在 Jetson 上运行
- jetson_power/fps/latency: `tegrastats` 读取
- tensorrt_speedup: TRT时延 / PyTorch时延
- onnx_compatible: 尝试导出 ONNX 是否成功

#### 七、环境信息（30+ 个）- 系统调用收集
- 硬件：GPU/CPU/RAM 信息
- 软件：OS/Python/PyTorch/CUDA/cuDNN 版本
- 实验设置：分辨率/BS/precision/seed
- 版本控制：commit hash/datetime

### 2️⃣ (a) Pairwise Depth / Pointmap Reconstruction

**数据集**: ScanNet, MegaDepth
**指标定义**:
- AbsRel = mean(|d_pred - d_gt| / d_gt)
- RMSE = √(mean((d_pred - d_gt)²))
- δ1 = % of pixels where max(d_pred/d_gt, d_gt/d_pred) < 1.25

**ScanNet 结果**:

| Method | AbsRel ↓ | RMSE ↓ | δ1 ↑ |
|--------|----------|--------|------|
| DUSt3R-512 | **0.094** | **0.35** | **0.915** |
| DUSt3R-1024 | 0.081 | 0.30 | 0.936 |

---

### 3️⃣ (b) Multi-view Depth / Pointmap Fusion

**数据集**: DTU, ETH3D
**指标定义**:
- Chamfer Distance (mm)
- Completeness (%)
- Accuracy (%)
- F-score = harmonic mean(completeness, accuracy)

**DTU 结果**:

| Method | Accuracy ↓ | Completeness ↓ | F-score ↑ |
|--------|------------|----------------|-----------|
| DUSt3R | 0.53 | 0.57 | 0.68 |
| DUSt3R-1024 | 0.48 | 0.51 | 0.73 |

## 📐 Step 4: 显存与内存指标测量 (2025-12-25)

### 测量方法
- `vram_peak`: FP32 模式，`torch.cuda.max_memory_allocated()`
- `vram_fp16`: 使用 `torch.amp.autocast('cuda', dtype=torch.float16)`
- `activation_memory`: vram_peak - model_size

### 执行命令
```powershell
cd third_party/dust3r
python -c "
import torch
from dust3r.model import AsymmetricCroCo3DStereo

model = AsymmetricCroCo3DStereo.from_pretrained('naver/DUSt3R_ViTLarge_BaseDecoder_512_dpt')
model.eval().to('cuda')

dummy = torch.randn(1, 3, 384, 512, device='cuda')
v1 = {'img': dummy, 'instance': ['t'], 'idx': 0, 'true_shape': torch.tensor([[384, 512]], device='cuda')}
v2 = {'img': dummy, 'instance': ['t'], 'idx': 1, 'true_shape': torch.tensor([[384, 512]], device='cuda')}

# FP32
torch.cuda.reset_peak_memory_stats()
with torch.no_grad(): model(v1, v2)
vram_fp32 = torch.cuda.max_memory_allocated() / 1e9

# FP16 (autocast)
torch.cuda.reset_peak_memory_stats()
with torch.no_grad():
    with torch.amp.autocast('cuda', dtype=torch.float16):
        model(v1, v2)
vram_fp16 = torch.cuda.max_memory_allocated() / 1e9
"
```

### 测量结果

| 指标 | 测量值 | 说明 |
|------|--------|------|
| **vram_peak** | **2.76 GB** | FP32, forward-only, BS=1 |
| **vram_fp16** | **3.85 GB** | autocast FP16（见注意事项） |
| **activation_memory** | **0.53 GB** | 估算值 |

### ⚠️ 注意事项

1. **FP16 显存反而更高**:
   - DUSt3R 模型内部有 `with torch.cuda.amp.autocast(enabled=False)` 强制禁用 autocast
   - 这是 DUSt3R 官方设计，确保数值稳定性
   - 因此 autocast 包装不会降低显存
   - **结论**：DUSt3R 不支持原生 FP16 推理

2. **vram_peak 与之前测量对比**:
   - 之前测量：2.58 GB
   - 现在测量：2.76 GB
   - 差异可能来自 CUDA 分配策略、输入格式差异
