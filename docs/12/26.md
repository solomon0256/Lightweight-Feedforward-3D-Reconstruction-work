## �️ Session 5: PQK 验证机制（两道门禁）

### 5.1 核心问题

在开始 PQK 实验前，需要解决两个风险：

| 风险类型 | 说明 | 解决方案 |
|----------|------|----------|
| **脚本逻辑错误** | 量化后输出字段对不上、尺度对齐变了、评测口径漂移 | Smoke Gate |
| **性能/精度崩溃** | 脚本对但模型崩了，需要跑大规模才知道 | Trend Gate |

**结论**：只靠 1-2 个样本跑通只能证明代码不报错，不能证明口径正确，更不能证明性能趋势。

### 5.2 两道门禁设计

#### Gate A: Smoke Gate（正确性门）

- **规模**: 16 对样本，2-5 分钟
- **检查**: Schema 断言 + Golden 对比 + 稳定性
- **目的**: 防止口径漂移

#### Gate B: Trend Gate（趋势门）

- **规模**: 200 对样本，30-60 分钟
- **检查**: 精度护栏 + 性能护栏 + 早停阈值
- **目的**: 防止精度/性能崩溃

### 5.3 创建的文件

| 文件 | 说明 |
|------|------|
| `docs/PQK_验证机制_两道门禁.md` | 完整验证机制文档 |
| `config/eval_contract.yaml` | 评测合同（冻结的评测配置） |
| `scripts/smoke_gate.py` | Smoke Gate 验证脚本 |
| `scripts/trend_gate.py` | Trend Gate 验证脚本 |

### 5.4 早停阈值配置

| 方法 | 精度红线 | 动作 |
|------|----------|------|
| **FP16** | delta1↓>1% 或 visloc↓>2% | 停，查口径 |
| **INT8 PTQ** | delta1↓>3% 或 absrel↑>10% | 判"趋势崩"，不上服务器 |
| **剪枝** | 每↓20% FLOPs，delta1↓>2% | 改剪枝策略 |

### 5.5 执行流程

```
Step 0: 冻结 Baseline ✅ (已完成)
Step 1: 建立 Smoke + Golden (一次性)
Step 2: 每次 PQK 先过 Smoke Gate (2-5分钟)
Step 3: 再过 Trend Gate (30-60分钟)
Step 4: 通过后才上服务器跑 Final
```

## 🚦 两道门禁简单说明（GPT 指导）

### 为什么需要？

**核心问题**：本地小电脑没法跑完整评测，怎么知道脚本写对了、模型没崩？

**GPT 的回答**："只靠 1-2 个样本跑通只能证明代码不报错，不能证明口径正确，更不能证明性能趋势。"

### Gate 1: Smoke Gate（正确性检测）

**做什么**：用 16 对固定样本，检查脚本有没有写错

```bash
# 1. 先用 baseline 跑一次，保存"标准答案"
python scripts/eval_depth_pose.py --max-pairs 16 --save-golden

# 2. 每次改完代码后，跑同样 16 对，对比
python scripts/smoke_gate.py --method Q --variant fp16
```

**检查 3 件事**：
| 检查项 | 怎么检查 |
|--------|----------|
| Schema | 输出字段名、shape、dtype 是否一致 |
| 数值 | 有没有 NaN/Inf |
| 结果 | 和"标准答案"差距是否在容忍范围内 |

**通过条件**：FP16 允许 <0.1% 偏差，INT8 允许 <1% 偏差

### Gate 2: Trend Gate（性能预警）

**做什么**：用 200 对样本，看指标有没有崩

```bash
python scripts/trend_gate.py --method Q --variant fp16 --num-pairs 200
```

**检查 3 件事**：
| 检查项 | 红线 |
|--------|------|
| absrel | 上升 >10% → 死刑 |
| delta1 | 下降 >3% → 死刑 |
| 延迟 | 必须下降（量化本来就是为了快） |

### 执行流程（一句话）

```
改代码 → Smoke(5分钟) → 过了? → Trend(1小时) → 过了? → 上服务器
                ↓ 不过              ↓ 不过
              查bug              调参数，别上服务器
```

### 核心思想

1. **Smoke**：防止你把代码写错了（字段名改了、尺度对齐变了）
2. **Trend**：防止模型真的崩了（精度暴跌、速度没提升）

**不过 Smoke 不做 Trend，不过 Trend 不上服务器！**
